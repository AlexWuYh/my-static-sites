ConfigSSH

Manage SSH config visually, connect in one click.

It reads and writes your ~/.ssh/config directly, with no separate host database. Changes are previewed as a diff and backed up before writing, and connections go through the terminal you already use. Without it, ssh, scp and VS Code Remote keep working as usual.

What it is

Your config stays yours, just easier to manage

Many SSH clients import your hosts into their own database, so you end up syncing two sets of config. ConfigSSH does not.

Features

Manage, edit and connect from one window

Host management

Browse by group with search, favorites and collapsing. Every field in the add form is marked required or optional with a hint and an example, mistakes are flagged at once, and a host can have a display name (Chinese is fine).

Safe editing

Edit HostName, User, Port, IdentityFile, ProxyJump and other common fields in a form, or edit the raw config. Diff preview before saving, backup before writing.

Quick connect

Double-click a host to connect. In any app, press the global shortcut ⌥⌘K or click the menu bar icon, search for a host and open the terminal.

Use your terminal

Terminal, Ghostty and Otty are detected automatically, other terminals can be configured by hand, and each host can open in a new window or a new tab.

Keys and key deployment

Index public keys and see which hosts use them, and generate Ed25519 / RSA keys. Enter a password once and the wizard installs the key on the server and switches the host to key login.

Encrypted backup and restore

The file you are about to change is backed up automatically. With a backup passphrase set, local snapshots and the iCloud copy are both encrypted, one master switch manages automatic backups, and the diff is previewed before any restore.

iCloud sync

When your config changes, an encrypted copy goes to iCloud Drive within seconds; on another Mac, preview the diff under Cloud devices and pull it. Always encrypted, and private keys are never uploaded.

Import and export

Export host config as a .zip, or as an encrypted .cssh file with its own passphrase; on import the passphrase is checked first and each file is previewed as a diff. No private keys.

Startup and updates

Optional launch at startup (off by default) keeps the global shortcut available; the About page links to the website and GitHub and can check for updates.

How it works

Three steps

Open the app

On launch it reads ~/.ssh/config and its Include files and groups hosts by source directory. This step only reads; it never writes.

Add or edit a host

Fill in the alias, address, user and port. You see the diff before saving, and nothing is written or backed up until you confirm.

Connect in one click

Double-click a host, or press ⌥⌘K to search, and the app opens ssh <alias> in your terminal.

Quick connect

Search anywhere, connect directly

No need to switch to the ConfigSSH window. The global shortcut and the menu bar icon both search hosts and open a terminal, and focus leaves your current app only after you pick a host.

How files are kept

How your config is stored

A group is a subdirectory and each new host is its own file. Existing config is not migrated; it is read and shown as it is.

Directory layout

~/.ssh/
├── config              ← global options + Include entry
└── config.d/
    ├── api.conf        ← ungrouped host, one file each
    └── Work/           ← a group = a subdirectory
        └── staging.conf

A few conventions

  • config is only the entry point: the first time you add a host, the app inserts two lines such as Include config.d/*.conf before the Host rules and shows them in the preview.
  • Existing Host blocks are read and shown as they are; the app does not move them.
  • A host can have a display name and its file is named after it: "Production API" is saved as config.d/Engineering/Production API.conf, and the form shows the "will be saved as" path live.
  • Deleting a group is previewed first and its hosts move to "Ungrouped"; on a name clash or unrecognized content it stops without overwriting any file.
Safety & privacy

Safety and privacy

It touches your SSH config, so every step leaves room to back out.

What it does

  • Shows a line-by-line diff and saves a backup before writing (the last 50 are kept by default, adjustable).
  • Re-checks the file version before writing, and keeps the other program's version and reports a conflict if it changed.
  • Replaces files atomically and refuses to write symlinks or paths outside ~/.ssh.
  • Reads only .pub public key files when indexing keys.

What it never does

  • Never stores SSH passwords, and everyday use does not read private key contents into the app.
  • Never runs ssh -G automatically, because Match exec can run local commands.
  • Never rewrites complex config it cannot locate safely through the simple form; such hosts stay read-only.
  • Never uploads private keys to iCloud, and never puts them in any snapshot or backup.

Local snapshots are encrypted by default: set a backup passphrase first. You can switch to unencrypted in Settings, and then a snapshot holds the config in plain text (host addresses, users, ports and key paths) that anyone who can read the file can see, so you get a risk confirmation first and the app keeps flagging "local snapshots are unencrypted".

Backup & restore

Backup and restore

Under Settings › Backup: status, backup passphrase and automatic backup, top to bottom.

Set a backup passphrase first

At least 12 characters. Encrypted local snapshots and the iCloud copy both use it. It is kept in this Mac’s keychain and never uploaded; if you lose it, those backups cannot be recovered. The keychain is read at most once per run, so choose Always Allow the first time.

Local snapshots

Config and Include files are saved encrypted by default, or switch to unencrypted behind a risk confirmation. The finest interval is once a day, skipped when nothing changed; the last 14 automatic snapshots are kept by default and your manual ones are never touched.

Sync to iCloud

Whenever the config changes, this Mac’s encrypted copy is uploaded within seconds, and saving several hosts in a row uploads once. You can also press Back up now at any time.

Browse and restore: click Browse and Restore, and selecting an encrypted snapshot unlocks it with the saved passphrase and lists its files; after Restore this snapshot you see a line-by-line diff and nothing is written until you confirm. A restore only writes config files back, never restores private keys, and does not delete files added after the snapshot. Without a passphrase, encrypted snapshots and iCloud sync do not run.

Snapshots hold config files only, never private keys. Back up your private keys your own way.

Import & export

Import and export

Take your host config to another Mac, or hand it to a colleague. Find it under Settings › Backup › Import and export.

Export

Click Export host config and choose a format:

  • Archive .zip (default): the files under config and config.d/ plus a checksum manifest. Not encrypted, so anyone who gets it can see your host addresses and users.
  • Encrypted file .cssh: set a passphrase just for this file (at least 12 characters); it is encrypted with AES-GCM and cannot be recovered if the passphrase is lost.

Neither format includes private keys. Include files outside ~/.ssh are not exported, and you are told how many were skipped.

Import

  • An encrypted file asks for its passphrase first and shows its contents only after it checks out; a wrong passphrase or a modified file is rejected outright and nothing is written.
  • A zip exported by ConfigSSH is checked file by file against its manifest, and modified files are rejected. A zip made with Finder or by hand can be imported too, but has no manifest, so check the diff yourself.
  • By default only host files are imported and your current main config is kept; to replace the global settings too, tick "Also overwrite the current main config".
  • Click Preview changes to see each file’s diff before confirming. Only files at the same path are added or overwritten, nothing else is deleted, and overwritten files are backed up first; files with reserved names such as keys or known_hosts, or with path traversal (../), are rejected.

Imported hosts not showing? If your current main config has no Include config.d/*.conf, the imported hosts will not show up yet. You are reminded after the import; add the Include by hand, or import again with the overwrite option ticked.

iCloud sync

Encrypted iCloud sync

Share one SSH config across several Macs, and only when you need it.

Encrypted on your Mac

Content is encrypted locally with AES-GCM, using a key derived from the backup passphrase. The passphrase is never uploaded, and every Mac uses the same one.

One file per Mac

Each device has its own Devices/<device-id>.cssh in iCloud Drive, so they never overwrite each other.

Preview before pulling

On another Mac, pick a device under Cloud devices and pull, and confirm after viewing each file’s diff; a pull only overwrites files at the same path, after a backup. Only config and the .conf files under config.d/ are synced.

Note: the app can only confirm a file was written to the local iCloud Drive folder, not that it reached the cloud, so check the sync status in Finder. If you lose the passphrase, the cloud copy cannot be decrypted. Absolute paths and IdentityFile locations may differ between Macs, so review them after pulling. Include files outside ~/.ssh are not uploaded; tick the setting that lets the cloud copy omit them, or automatic sync pauses. After a passphrase change, if this Mac’s existing cloud file cannot be decrypted, automatic sync stops instead of overwriting and waits for your confirmation under Cloud devices and pull.

Download

Download and install

Requires macOS 14 Sonoma or later on Apple Silicon (arm64). Connections use the OpenSSH that ships with macOS.

Preview: the pre-release package is neither signed nor notarized. It is for personal preview only, so please do not redistribute it. On first launch macOS warns that it cannot verify the developer.

Download the pre-release Recommended

Download ConfigSSH-vX.Y.Z-unsigned-macos-arm64.zip and SHA256SUMS.txt from the Releases page, put them in one folder and verify:

shasum -a 256 -c SHA256SUMS.txt

Unzip it and drag ConfigSSH.app into Applications. On first launch, open System Settings › Privacy & Security and click "Open Anyway" at the bottom of the page.
